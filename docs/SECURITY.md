# 安全说明

> **本系统的定位是「单位内网自用」，不是面向公网的服务。**
>
> 它假定运行环境是：单位内网里的一台 Windows 机器，员工通过局域网 IP 或手机
> 访问，同事之间没有恶意流量。系统没有做多租户隔离、没有做防爬、没有做
> WAF 级别的防护，也**不应该**直接暴露到公网。
>
> 下面记录的是这个定位下已经实现的防护，以及部署到内网时必须补上的运维动作。

配套文档：[ARCHITECTURE.md](ARCHITECTURE.md)、[API.md](API.md)、
[DATA.md](DATA.md)、[TROUBLESHOOTING.md](TROUBLESHOOTING.md)、[RELEASE.md](RELEASE.md)。

## 1. 威胁模型概览

| 资产 | 主要风险 | 已实现的防护 |
| --- | --- | --- |
| 员工工资数据 | 越权查看他人工资 | 接口不接受工号参数，身份完全来自服务端签名的令牌 |
| 员工口令 | 员工表泄露导致口令暴露 | PBKDF2-HMAC-SHA256 哈希 + 常量时间比较 |
| 会话令牌 | 令牌被伪造或窃取 | HMAC-SHA256 签名、常量时间校验、30 分钟有效期 |
| 暴力破解 | 反复试口令 | 按 IP + 工号双维度限流，15 分钟 5 次即锁 15 分钟 |
| 跨站攻击 | 恶意网站读工资条 | 默认只允许同源；令牌放 `Authorization` 头而不是 Cookie |
| 操作留痕 | 事后无法追查 | 审计日志记录登录、查询、导出等动作 |
| 源码泄露 | 敏感文件进版本库 | `.gitignore` 排除 `data/` 下的 Excel、密钥、证书、日志 |

## 2. 口令存储

### 2.1 哈希算法

实现在 `src-tauri/src/password.rs`：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 算法 | PBKDF2-HMAC-SHA256（RFC 8018） | 纯 Rust 实现，无外部依赖 |
| 迭代次数 | **210000** | 单次校验约 0.1–0.2 秒；离线爆破代价足够高，员工登录又不会明显卡顿 |
| 盐长度 | 16 字节 | 每人一个随机盐，用 `OsRng` 生成 |
| 派生密钥长度 | 32 字节 | |
| 最大迭代次数 | 1000000 | 迭代次数存在哈希串里，不设上限的话，攻击者把员工表里的次数改成极大值就能让服务在登录时疯狂空转。超限直接判定口令不匹配 |
| 存储格式 | PHC 标准字符串 | 见下 |

```
$pbkdf2-sha256$210000$<盐(base64)>$<派生密钥(base64)>
```

盐与派生密钥用标准 base64（去掉结尾的 `=`）编码。选 PHC 格式有两个考虑：

1. 将来换成 Argon2id 之类的新算法时，存量数据的格式不用改，只需按前缀分派；
2. Python 标准库的 `hashlib.pbkdf2_hmac` 能算出同样的结果，
   因此批量迁移脚本不需要任何第三方依赖。

`src-tauri/src/password.rs` 里有一个跨实现的测试向量：用 Python
`hashlib.pbkdf2_hmac` 算出的已知结果，Rust 侧必须算出完全一样的字节。
这保证迁移脚本与后端的实现不会悄悄分叉。

### 2.2 明文口令兼容

**明文口令只用于迁移，不作为正式方案。**

判定逻辑很简单：值以 `$pbkdf2-sha256$` 开头就按哈希校验，否则按明文比对。
两种格式可以混在同一张员工表里，登录时按值的形式自动分派，员工无感知。

这样设计是为了让存量数据能平滑升级：

- 不需要停机改表，改完哈希表换上去即可；
- 迁移过程中新旧账号可以并存。

但明文口令是历史行为——员工表原本直接保存明文（与 Python 原版一致），
而**初始口令往往就是 HR 登记的紧急联系人号码**。表一旦泄露就等于泄露了
每个人的联系方式与初始口令。

**正式使用前必须做这一步：**

```bash
# 先看会改什么
python scripts/hash_passwords.py --dry-run

# 原地替换，原文件备份为 data/员工列表.xlsx.bak
python scripts/hash_passwords.py --in-place

# 确认新表可以正常登录后，删掉明文备份
```

脚本只处理表头里带「密码」二字的列。表里没有「密码」列时脚本会直接报错退出，
**绝不**把手机号 / 紧急联系人号码那几列当成口令处理——那等于毁掉了联系方式。
已经是哈希值的单元格原样保留，重复执行是安全的。

### 2.3 口令比对

明文与哈希两条路径都用**常量时间**比较（`constant_time_eq`），
不通过响应时间差来推测口令。`auth.rs` 里校验令牌签名用的也是同一套写法。

### 2.4 口令列的识别

后端识别「口令列」的规则（`excel_parser::PASSWORD_KEYWORDS`）：
`密码` → `手机号` → `联系电话` → `紧急联系人` → `紧急联系人号码`，按顺序取第一个命中的。

这是与 Python 原版一致的历史行为，**初始口令就是 HR 登记的紧急联系人号码**。
建议在正式使用的员工表里加一列真正的「密码」，并在迁移脚本的
`--in-place` 之后通知员工改口令。

## 3. 令牌与密钥

### 3.1 会话令牌

| 项 | 值 |
| --- | --- |
| 格式 | `base64url(载荷).hex(HMAC-SHA256(载荷))` |
| 载荷 | `{ employee_id, name, dept, exp }` |
| 有效期 | 30 分钟（`AuthContext::session_ttl_minutes`） |
| 签名算法 | HMAC-SHA256 |
| 存储 | 无状态，服务端不存令牌 |

无状态的好处是服务重启不影响已登录员工；代价是**没有服务端吊销能力**
——令牌一旦签发，在有效期内无法单独作废。员工「退出登录」时服务端只记一条
审计事件（`LOGOUT`），由客户端清除本地令牌。

过期后前端收到 401 会自动清除本地令牌并跳回登录页，提示「登录状态已过期，请重新登录」。

### 3.2 签名密钥 `data/secret.key`

| 项 | 说明 |
| --- | --- |
| 位置 | `data/secret.key`（可用 `SALARY_DATA_DIR` 改写） |
| 格式 | 32 字节随机数的十六进制文本（64 个字符） |
| 生成 | 首次启动时用 `OsRng` 生成并写入（`server::load_or_create_secret_key`） |
| 失效处理 | 文件内容不是合法十六进制、或解码后不足 32 字节，会**重新生成**并打一条告警日志 |
| 影响 | 密钥一旦更换，所有已签发令牌立即失效，员工需要重新登录 |

**保管要求：**

1. 文件**绝不能进版本库**（`.gitignore` 已排除 `data/secret.key`）。
2. 不要通过微信、邮件、网盘明文传输。需要备份时用加密介质，并记录交接。
3. 不要把密钥提交到 CI 的日志里。CI 用的是测试专用密钥
   （`b"integration-test-secret-key"`），与生产无关。
4. 多台机器部署时，每台机器有自己的 `data/` 目录，因此密钥各不相同——
   这意味着**跨机器的令牌不通用**，这是预期行为。

**怀疑密钥泄露时的处置：** 删除 `data/secret.key`（下次启动会重新生成），
所有员工需要重新登录；同时检查 `data/audit.log` 里有没有异常的 `VIEW` 记录。

## 4. 登录限流

实现在 `src-tauri/src/auth.rs` 的 `RateLimiter`，两个维度**独立计数、独立锁定**：

| key | 含义 |
| --- | --- |
| `ip:<客户端 IP>` | 同一个 IP 的失败次数 |
| `user:<输入的工号>` | 同一个工号的失败次数，无论从哪个 IP 来 |

| 参数 | 值 |
| --- | --- |
| 时间窗 | 15 分钟（`window_seconds`） |
| 阈值 | 5 次（`max_attempts`） |
| 锁定时长 | 15 分钟（`lock_seconds`） |

行为：

- 登录前先检查两个 key 是否已被锁，任一被锁就返回 **429**，
  提示「账号或网络已被临时锁定，请在 N 秒后重试」；
- 失败时两个 key 各记一次，达到阈值就锁；
- 登录成功时清除两个 key 的失败计数与锁定。

双维度的用意是同时挡住两类攻击：**分布式猜口令**（同一工号从多个 IP 来，
被 `user:` 维度挡住）与**单点暴力破解**（一个 IP 挨个试很多工号，
被 `ip:` 维度挡住）。

限流状态在内存里，进程重启即清空。这是刻意的：重启服务不应该把员工
锁在门外 15 分钟。

> 限流是**防暴力破解**的措施，不是访问控制。系统没有做「每员工每分钟查询次数」
> 之类的配额控制。

## 5. 跨域策略

**默认只允许同源。** `SALARY_ALLOW_ORIGIN` 未设置或为空时，服务不返回任何
CORS 响应头，浏览器只能同源访问（`server::cors_policy`）。

| `SALARY_ALLOW_ORIGIN` 取值 | 效果 |
| --- | --- |
| 不设置 / 空 | 只允许同源（默认） |
| `https://hr.example.com` | 只放行这一个来源 |
| `*` 或任意不含 `://` 的非空值 | 放行任意来源（兼容旧版行为） |

令牌放在 `Authorization` 头里而不是 Cookie，因此放开跨域**不会**让别的网站
自动带上用户的令牌。但仍建议指定具体来源，别把服务暴露给任意网站。

本系统的正常用法（同源访问）根本不需要动这个变量。

## 6. HTTPS 与自签名证书

| 项 | 说明 |
| --- | --- |
| 实现 | rustls，**只启用 `ring` 特性**（不引入 `aws-lc-rs` 的 C 工具链依赖） |
| 证书 | `rcgen` 生成的自签名证书，SAN 包含 `localhost` 与 `127.0.0.1` |
| 位置 | `data/certs/server.crt` 与 `data/certs/server.key` |
| 端口 | HTTP `P`（默认 5001），HTTPS `P + 1`（默认 5002） |
| 生成时机 | 首次启动时自动生成；证书与私钥都存在才复用 |

**自签证书的定位是「防明文窥探」，不是身份认证。**

- 它能保证局域网内抓包看到的不是明文密码；
- 但浏览器不信任它，首次访问要手动确认「继续访问」；
- 证书里的 SAN 只有 `localhost` 与 `127.0.0.1`，**用局域网 IP 访问 HTTPS
  会提示域名不匹配**。

因此内网实际使用中，**HTTP（5001）才是主入口**；HTTPS 作为「不想让密码
明文过网」的补充。如果确实需要让手机在 Wi-Fi 下用 HTTPS 访问，
请自行为内网域名签发一张受信任的证书并替换 `data/certs/` 下的两个文件。

`data/certs/` 已被 `.gitignore` 排除，不要把私钥提交到版本库。

## 7. 审计日志

| 项 | 说明 |
| --- | --- |
| 位置 | `data/audit.log`（JSON Lines，每行一条 JSON） |
| 格式 | `{ timestamp, ip, action, employee_id, employee_name, detail }` |
| 时间戳 | RFC3339（UTC） |
| 轮转 | 超过 **5 MB** 时，当前日志改名为 `data/audit.log.1`，只保留最近一份备份 |
| 写入方式 | 进程内互斥锁 + 一次写完整行（避免并发时两条记录挤到同一行） |
| 读取 | **只写文件，网页端不提供读取接口** |

记录的动作：

| action | 触发时机 | detail |
| --- | --- | --- |
| `LOGIN` | 登录成功 | 「登录成功」 |
| `LOGIN_FAIL` | 登录失败（口令错 / 工号不存在） | 「登录失败」 |
| `LOGIN_BLOCKED` | 触发限流锁定 | 「触发登录限流」 |
| `LOGOUT` | 退出登录 | 「退出登录」 |
| `VIEW` | 查询某个月的工资条 | 该月，如 `2026-10` |
| `EXPORT_IMG` | 导出工资条截图 | 该月 |
| `EXPORT_PDF` | 导出工资条 PDF | 该月 + 说明 |
| `PRINT` | 打印工资条 | 该月 |

### 客户端 IP 的取值

**只取 TCP 对端地址**（`req.peer_addr()`），不读 `X-Forwarded-For` / `X-Real-IP`。

本系统是局域网直连部署、**没有反向代理**，这两个头可以被客户端任意伪造。
拿它们做审计依据会让日志失去意义（与 Python 原版一致）。

如果将来加了反向代理，需要相应修改 `handlers::client_ip`，
否则审计日志里的 IP 全是代理的地址。

### 查看方式

```powershell
# 最近 20 条
Get-Content data\audit.log -Tail 20 -Encoding UTF8

# 某人查过哪些月份
Select-String -Path data\audit.log -Pattern '"employee_id":"001"'
```

日志文件是敏感数据（含工号与姓名），同样不入库。

## 8. 敏感文件与 `.gitignore`

### 8.1 `data/` 目录的规则

`data/` 是运行时数据目录，里面有：

| 文件 | 敏感度 | 是否入库 |
| --- | --- | --- |
| `员工列表.xlsx` | 高（含口令或口令哈希、姓名、部门、手机号） | **否** |
| `salary/*.xlsx` | 极高（全员工资明细） | **否** |
| `secret.key` | 极高（令牌签名密钥） | **否** |
| `certs/server.key` | 高（HTTPS 私钥） | **否** |
| `audit.log` | 高（含工号、姓名、查询记录） | **否** |
| `port.txt` | 低 | 否（`.gitignore` 已排除） |
| `fields.txt` | 低（只有字段名与显示策略，不含个人数据） | **未被 `.gitignore` 排除**，提交前自己确认 |
| `README.md`、`.gitkeep` | 无 | 是 |

`.gitignore` 里的相关规则：

```gitignore
# 数据文件（含敏感信息，绝不入库）
data/**/*.xlsx
data/**/*.xls
data/**/*.log
data/secret.key
data/port.txt
data/certs/
!data/.gitkeep
```

> `data/**/*.xlsx` 这类规则**只排除文件，不排除目录本身**，
> 所以 `data/` 目录在仓库里仍然存在（有 `data/README.md` 与 `data/.gitkeep` 撑着）。

### 8.2 `.gitignore` 还管什么

| 规则 | 原因 |
| --- | --- |
| `/target/` | Rust 构建产物 |
| `node_modules/`、`src-tauri/dist/` | 前端依赖与构建产物 |
| `**/.mimosa/` | 本地工具的状态目录 |
| `*.tsbuildinfo` | TypeScript 增量编译缓存 |
| `tray-panel.png` 等 | 本地调试截图 |
| `__pycache__/`、`*.py[cod]` | Python 字节码缓存 |
| `.env`、`.env.local` | 环境变量文件 |

### 8.3 提交前的自查

```powershell
git status --short
git ls-files data/
```

第二条命令应当**没有输出**——`data/` 下除了 `README.md` 与 `.gitkeep` 之外
不应该有任何被跟踪的文件。

如果误提交了敏感文件，仅仅删掉文件是不够的（历史里还在），
需要用 `git filter-repo` 之类的工具清理历史，并**立即更换 `data/secret.key`
与自签名证书**。

## 9. 部署到内网时的建议

### 9.1 必须做的

1. **换掉示例账号的口令。**
   示例数据里的 `001` / `salary2026`、`003` / `admin2026` 是公开的。
   正式使用前删除示例员工，或至少改掉这些口令。

2. **把员工表的口令升级成哈希。**

   ```bash
   python scripts/hash_passwords.py --in-place
   ```

   升级后删除 `data/员工列表.xlsx.bak`（明文备份）。

3. **让每位员工改掉初始口令。**
   初始口令往往是紧急联系人号码，这个号码本身也是隐私。

4. **限制防火墙来源。**
   不要「放行任何来源」。只放行单位内网网段：

   ```powershell
   netsh advfirewall firewall delete rule name="工资查询系统 5001"
   netsh advfirewall firewall add rule name="工资查询系统 5001" dir=in action=allow protocol=TCP localport=5001 remoteip=192.168.1.0/24
   ```

   托盘面板的「放行防火墙端口」按钮放行的是**所有来源**，
   适合临时测试，长期使用请手工改成限定网段。

5. **限制服务监听范围。**
   服务固定监听 `0.0.0.0`。如果这台机器**不需要**被其它电脑访问，
   就别开放端口，只在本机使用。

6. **保护 `data/` 目录的文件系统权限。**
   只有运行服务的账户和 HR 负责人的账户应该能读 `data/`。
   Windows 上用 NTFS ACL 收紧 `data/` 及其父目录的读取权限。

7. **不要暴露到公网。**
   不要做公网端口映射，不要放到公网云服务器上给外部员工用。
   本系统没有 WAF、没有多租户隔离、没有验证码、没有登录 IP 白名单，
   暴露到公网等于把一个「只能靠工号+口令进门」的服务放在开放互联网上。

8. **不要让 `SALARY_ALLOW_ORIGIN` 指向 `*`。**
   默认不同源即可；确需跨域时写具体来源。

### 9.2 建议做的

| 建议 | 理由 |
| --- | --- |
| 定期备份 `data/员工列表.xlsx` 与 `data/salary/` | Excel 是唯一的数据源，没有数据库可以重建 |
| 定期归档 `data/audit.log` | 便于事后追溯，也避免文件无限增长（虽然有 5 MB 轮转） |
| 用组策略统一分发端口与 `SALARY_DATA_DIR` | 多台机器时保持一致 |
| 记录 `data/secret.key` 的交接 | 换机器时不丢密钥，员工不必集体重新登录 |
| 用 `SALARY_DATA_DIR` 把数据放到单独的加密卷 | 笔记本丢失时数据不至于直接泄露 |

### 9.3 环境变量速查

| 变量 | 默认值 | 安全影响 |
| --- | --- | --- |
| `SALARY_DATA_DIR` | `data/` | 指向别处不会改变权限模型，仍要自己收紧 ACL |
| `SALARY_PORT` | `5001` | 端口是成对的，上限 65534 |
| `SALARY_WEB_DIR` | 自动探测 | 指向别处即可换掉前端页面（仅在可信环境里做） |
| `SALARY_NO_BROWSER` | — | 设为 `1` 时不自动打开浏览器 |
| `SALARY_ALLOW_ORIGIN` | — | **写 `*` 等于放开跨域**，谨慎 |
| `RUST_LOG` | `salary_app=debug,actix_web=info` | 设为 `trace` 会把请求细节打进日志，注意别在共享终端里开 |

## 10. 安全相关的已知限制

诚实地列出来，方便评估：

1. **没有服务端吊销令牌的能力。** 令牌在 30 分钟内无法单独作废。
2. **没有账号锁定后的自助解锁。** 被锁 15 分钟只能等，或重启服务（内存态限流会清空）。
3. **没有登录 IP 白名单。** 任何能连到端口的人都可以尝试登录，只受限流约束。
4. **没有验证码或二次验证。**
5. **限流状态在内存里。** 多实例部署或重启会清空计数。
6. **自签证书的 SAN 不含局域网 IP。** 用 IP 访问 HTTPS 会有域名不匹配提示。
7. **审计日志不防篡改。** 能写 `data/` 的人可以改日志。需要防篡改就得配合
   外部日志采集。
8. **员工表本身就是明文可读的 Excel。** 除了口令列，其余全是明文。
   文件系统权限是最后一道防线。
