# 数据格式

所有数据文件都放在 `data/` 目录（可用 `SALARY_DATA_DIR` 环境变量改写）。

```
data/
├── 员工列表.xlsx            必需
├── salary/                  必需：每月一个工资表
│   ├── 2026 年 10 月员工工资.xlsx
│   └── 2026 年 09 月员工工资.xlsx
├── fields.txt               可选：字段显示配置
├── secret.key               自动生成：令牌签名密钥
├── certs/                   自动生成：自签名证书
└── audit.log                自动生成：审计日志
```

> Excel 文件里含有敏感信息，`.gitignore` 已排除 `data/` 下的 `.xlsx` / `.xls` 文件。

## 员工列表.xlsx

第一行是表头，其余每行一名员工。

| 列名（识别方式） | 是否必需 | 说明 |
| --- | --- | --- |
| 工号 / 员工号 / 员工编号 / 账号 | 必需 | 登录用户名 |
| 密码 / 手机号 / 联系电话 / 紧急联系人 / 紧急联系人号码 | 必需 | 登录口令。找不到「密码」列时依次回落到后面的列——**初始密码就是 HR 登记的紧急联系人号码** |
| 姓名 / 名字 | 可选 | 显示在工资条上 |
| 部门 / 科室 | 可选 | 显示在工资条上 |
| 管理员 / 是否管理员 / 角色 | 可选 | 取值为「是」「管理员」「1」「true」等时，该员工拥有管理员权限 |
| 离职 / 在职状态 / 状态 | 可选 | 取值为「是」「离职」「已离职」等时，该账号不允许登录 |

列名的识别规则：**先精确匹配，再模糊匹配**。

- 精确匹配优先，所以表里同时有「工号」和「工号状态」时会选「工号」；
- 同一轮内关键字的顺序优先于列的顺序，因此「密码」列总是优先于「手机号」列；
- 模糊匹配作为兜底，例如「员工工号」也能识别成工号列。

示例：

| 工号 | 姓名 | 部门 | 密码 | 手机号 | 角色 | 在职状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 001 | 张三 | 工程部 | ******** | 138… | 员工 | 在职 |
| 003 | 王五 | 人力资源部 | ******** | 138… | 管理员 | 在职 |

说明：

- 工号列按**文本**存放时前导零会保留（`001`）；存成数字时登录输入 `1` 也能匹配上。
  工资表与员工表用的是同一套匹配规则，因此两张表里一个是数字、一个是文本也能对上。
- 缺少工号列或密码列时，登录会直接被禁用并返回明确的错误提示。

### 口令：明文还是哈希

「密码」列里的值可以是**明文**，也可以是**哈希**（PBKDF2-HMAC-SHA256），
两种格式可以混在同一张表里，登录时按值的形式自动分派，员工无感知。

哈希串的格式是 PHC 标准字符串：

```
$pbkdf2-sha256$210000$<盐(base64)>$<派生密钥(base64)>
```

- 前缀 `$pbkdf2-sha256$` 用来识别哈希值；
- 中间的数字是迭代次数，与 Rust 侧 `password.rs` 的 `ITERATIONS` 一致；
- 盐与派生密钥用标准 base64（去掉结尾的 `=`）编码。

明文口令是历史行为，与 Python 原版一致。**建议升级成哈希**，避免员工表一旦泄露
就直接暴露出每个人的口令（初始口令往往就是紧急联系人号码）。

批量升级用仓库里的脚本（只依赖 Python 标准库）：

```bash
# 先看看会改哪些口令，不写文件
python scripts/hash_passwords.py --dry-run

# 生成新表：data/员工列表-哈希版.xlsx
python scripts/hash_passwords.py

# 原地替换，原文件备份为 员工列表.xlsx.bak
python scripts/hash_passwords.py --in-place
```

脚本只处理表头里带「密码」二字的列。表里没有「密码」列时脚本会直接报错退出，
不会去动手机号 / 紧急联系人号码那几列。已经是哈希值的单元格原样保留，
所以重复执行是安全的。

### 两种员工表结构

后端与 Python 原版一样，支持两种员工表结构：

**标准模式**（推荐）——首行是表头，每行一名员工：

| 工号 | 姓名 | 部门 | 密码 | 手机号 | 角色 | 在职状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 001 | 张三 | 工程部 | \*\*\*\*\*\*\*\* | 138… | 员工 | 在职 |

**原始模式**——没有表头，**每一列是一名员工**，前 5 行依次是工号、密码、姓名、部门、管理员：

| 001 | 002 | 003 |
| --- | --- | --- |
| \*\*\*\*\*\*\*\* | \*\*\*\*\*\*\*\* | \*\*\*\*\*\*\*\* |
| 张三 | 李四 | 王五 |
| 工程部 | 财务部 | 人力资源部 |
| 员工 | 员工 | 管理员 |

只要表头里出现了任意一个标准字段名（工号、姓名、部门、密码…）就按标准模式解析，否则按原始模式解析——判定规则与 Python 原版一致。

## salary/ 下的工资表

每个月的工资表一个文件。**文件名必须包含年月**，后端按以下顺序匹配：

| 写法 | 示例 |
| --- | --- |
| 年 / 月 | `2026 年 10 月员工工资.xlsx`、`2026年5月工资表.xlsx` |
| 分隔符 | `2026-10 工资.xlsx`、`2026_10 工资.xlsx`、`2026/10 工资.xlsx` |
| 紧凑写法 | `202605 工资.xlsx` |

同一个年月的多个文件都会出现在月份列表里，但查询时只取第一个。

工资表的列没有固定要求，唯一的硬性要求是包含一列能识别出员工的列：

| 列名（识别方式） | 是否必需 | 说明 |
| --- | --- | --- |
| 员工号 / 工号 / 员工编号 / 账号 | 必需 | 与员工列表里的工号对应 |
| 其它列 | 可选 | 原样返回给前端，列名即工资条的字段名 |

示例：

| 员工号 | 姓名 | 部门 | 基本工资 | 岗位工资 | 绩效工资 | 津贴 | 扣款 | 社保 | 个税 | 本月实发工资 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 001 | 张三 | 工程部 | 10280 | 1820 | 2240 | 500 | 360 | 1079.4 | 790.06 | 12610.54 |

数字单元格会去掉多余的尾随零（`8000.00` 显示为 `8000`），空单元格返回空字符串。

## fields.txt（可选）

控制工资条里哪些字段显示，每行一条 `字段名 = 策略`：

```
# 策略取值：show / 显示 / hide / 隐藏 / auto / 跟随
绩效工资 = hide
本月实发工资 = show
```

- `auto`（默认）：值为空或为 `0` 时隐藏，否则显示；
- `show`：无论取值如何都显示；
- `hide`：始终隐藏。

以 `#` 开头的行会被忽略。

## 生成示例数据

仓库里提供了一个只依赖 Python 标准库的生成脚本，用来快速跑通流程：

```bash
python scripts/generate_sample_data.py --data-dir data --months 3
```

它会生成 5 名员工（含 1 名管理员、1 名已离职）和最近 3 个月的工资表。**正式使用前请用真实数据替换。**
