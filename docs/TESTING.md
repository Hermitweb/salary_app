# 测试策略

这个项目的测试分四层，越靠下越贴近真实运行环境。

| 层 | 位置 | 跑的是什么 | 典型耗时 |
| --- | --- | --- | --- |
| 单元测试 | 各模块的 `#[cfg(test)]` | 单个函数的逻辑 | < 1s |
| 集成测试 | `src-tauri/tests/` | HTTP 接口（服务挂在测试进程内） | < 1s |
| 端到端测试 | `src-tauri/tests/e2e_test.rs` | 真实进程 + 真实 TCP | ~1s |
| 性能基准 | `src-tauri/benches/` | 各条热路径的耗时 | 数十秒 |

托盘面板是 Windows 原生窗口，没有自动化的 UI 测试；它的行为靠
「逻辑抽出来测 + 手工走查」保证（见 [面板部分](#托盘面板怎么测)）。

---

## 怎么跑

```bash
# 全部测试（单元 + 集成 + 端到端）
cargo test --workspace

# 只跑某一个
cargo test -p salary-app-backend
cargo test -p salary-app-backend --test e2e_test
cargo test -p salary-tray

# 带输出（看被跳过的用例）
cargo test --workspace -- --nocapture

# 性能基准
cargo bench --workspace
# 或者连真实网络延迟一起测（需要服务已经跑起来）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\bench.ps1
```

一键跑完所有检查（格式、lint、测试、前端构建）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify.ps1
```

> **测试依赖示例数据。** 集成测试要读 `data/salary/` 下的工资表，
> 仓库里不放真实数据，所以第一次跑要先生成：
>
> ```bash
> python scripts/generate_sample_data.py
> ```
>
> 少了这一步，用例会打印「示例数据缺失，跳过」然后报 **ok**——
> 测试是绿的，但什么都没验证。CI 的两个 job 都会先生成示例数据。

## 用例清单

### 单元测试（后端，41 个）

| 模块 | 覆盖的点 |
| --- | --- |
| `password` | PBKDF2 向量、明文兼容、每条哈希盐不同 |
| `auth` | 令牌签发/校验、过期、篡改、限流锁定 |
| `excel_parser` | 列名精确/模糊匹配、原始模式员工表、字段名归一化、配置键与表头同口径 |
| `models` | 字段三态语义、空值与 0 的判定（与 Python 版一致） |
| `handlers` | 工号匹配口径（数字/文本）、文件名里的年月解析 |
| `port` | 端口范围与解析 |
| `audit` | 日志轮转与保留 |
| `server` | CORS 策略 |

### 集成测试（`src-tauri/tests/integration_test.rs`，17 个）

服务用 actix 的 `test::init_service` 挂在测试进程内，走真实的路由与处理器：

- 登录成功 / 口令错误 / 已停用账号
- 未带令牌访问受保护接口 → 401
- 连续失败触发锁定
- 可查询月份列表（倒序、去重）
- 查工资：命中本人记录、参数校验、月份缺失
- 已删除的管理员接口 → 404
- 前端静态资源的缓存头与条件请求

### 字段配置测试（`src-tauri/tests/field_config_test.rs`，1 个）

单独成文件是因为它会改写数据目录里的 `fields.txt`，跟别的用例放一起会互相干扰。

覆盖 `data/fields.txt` 的三态语义真的作用到接口返回的表头上：
「跟随」空值不展示、有值展示；「显示」强制展示；「隐藏」强制不展示；
以及配置键前后的空白不影响匹配。

### 端到端测试（`src-tauri/tests/e2e_test.rs`，1 个）

**真的起一个 `salary-app-backend` 进程**，用 TCP 说 HTTP：

1. 服务起来 → `/healthz` 返回 200
2. 不带令牌查月份 → 401
3. 登录 → 拿到令牌
4. 查可查询月份 → 查工资 → 表头里有姓名、本月实发工资
5. 写 `fields.txt` 把某字段设为隐藏 → **再查一次，该字段消失**（配置立即生效）
6. 错误口令 → 401

只覆盖只挂在本进程内的测试覆盖不到的东西：端口解析、自签证书、
数据目录初始化、进程退出。

> 端到端测试里的 HTTP 客户端是手写的极简实现（`std::net::TcpStream`），
> 不引第三方 HTTP 依赖：这个仓库不为了跑测试多一份供应链。

### 托盘面板的测试（`tray/`，9 个）

| 用例 | 覆盖的点 |
| --- | --- |
| `fields::state_cycles` | 三态循环顺序 |
| `fields::saved_config_round_trips_and_keeps_manual_edits` | 保存后能读回来；注释、空行与无法识别的行原样保留 |
| `fields::saving_twice_keeps_the_same_line_order` | 连存两次，行序不变（文件不反复 diff） |
| `service::*` | 端口范围、进程识别、监听状态识别 |
| `tray/tests/service.rs` | 面板启停服务真的能起停 |

## 托盘面板怎么测

面板是 Windows 原生窗口（GDI 自绘），没有 UI 自动化框架，
所以分成两部分：

**逻辑抽出来测。** 能独立成函数的逻辑不放进窗口过程里：
字段发现与配置读写在 `tray/src/fields.rs`（有单元测试），
状态快照与动作分发在 `tray/src/panel.rs`（靠集成测试间接覆盖）。

**交互手工走查。** 走查清单：

| 场景 | 期望 |
| --- | --- |
| 悬停按钮 | 只重绘按钮那一小块，不整窗重绘 |
| 点击导航 | 内容区与侧边栏选中态一起变，其余不动 |
| 滚轮滚动列表 | 只重绘列表区，滚动条跟着走 |
| 切换主题 | 整窗换色；标题栏、图标、托盘图标一起换 |
| 缩放窗口 | 布局跟着重排：宽度变化时卡片重排，高度变化时字段列表多显示几行 |
| 未选中字段点「切换状态」 | 顶栏给出提示，不是毫无反应 |
| 保存字段配置 | 顶栏提示保存了几个字段；`data/fields.txt` 内容正确 |
| 访问地址卡片 | 只显示局域网地址，不显示 localhost；HTTP 与 HTTPS 两行 |
| 复制按钮 | 点「复制」后剪贴板里就是那条地址；「复制全部信息」里是地址+端口+登录说明 |
| 支持访问的网络 | 读 `data/networks.txt`，✓ / ✗ 标出是否支持访问；文件缺失时不显示条目 |
| 查看日志 | 用记事本打开 `data/audit.log`；日志还不存在时给提示而不是报错 |
| 登录提示 | 显示「账号 = 工号，密码 = 紧急联系人号码」 |
| 服务意外退出 | 面板自动把它拉起来，并提示「已自动恢复」 |
| 服务在跑时退出托盘 | 弹确认框，不直接退 |
| 使用手册页 | 能打开、能滚动，内容完整 |
| 放一份新月份工资表 | 字段列表自动更新，底部标出来源张数变了 |
| 图标 | 侧边栏 logo、标题栏、任务栏、托盘是同一张原版图标 |
| 查不存在的月份 | 回落到最新一份工资表，并提示实际给的是哪个月 |

**手测的辅助脚本**：

```powershell
# 截托盘面板的图（整窗，含标题栏）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\print-window.ps1
```

## 加测试的约定

- **测的是行为，不是实现。** 断言「接口返回的表头里没有那个字段」，
  而不是「内部调用了几次某个函数」。
- **用例之间不能互相影响。** 会写同一个文件（`fields.txt`、数据目录）的用例
  要单独成文件（独立测试二进制 = 独立数据目录），或自己准备临时目录。
- **缺数据要跳过，不要假通过。** 跳过时**必须打印原因**，
  否则 CI 上会出现「全是绿的，但什么都没测」的情况。
- **路径从 `paths.rs` 取**，测试里也用 `env!("CARGO_MANIFEST_DIR")` 推仓库根目录，
  不要写死 `../../data` 这种相对层级（少退一级、多退一级都会静默拿不到数据）。
- 注释写「为什么测这个」，不写「测了什么」。
